# Rule signals

Ten rules, no model. Each is one SQL statement (rules 6-9 share one temp table of masked shapes; their `detail` ends with ` · shape: ` and the masked error or command, a ready cluster key) in `src/tracelens/signals.py`. Every row cites `file:line` in the archive. Fixtures in `tests/fixtures/build.py` mark each expected positive (+) and negative (-).

| Signal | Fires on | Cites | Blind spots |
|---|---|---|---|
| `repeated_failure` | the same tool with byte-identical input fails again in one session with no `Edit`/`Write`/`MultiEdit`/`NotebookEdit`/`apply_patch` call in between. Exit 130 and exit 1 from `git diff`, `diff`, `grep`, `rg`, `cmp`, `test` do not count as failures | the first blind repeat | a retry with a trivially changed input is not caught; a fix made through Bash (`sed -i`) does not count as an edit |
| `approval_stall` | Claude: a call's result arrives > 20 min after the call and the tool is not one that legitimately blocks (`Agent`, `Task`, `TaskOutput`, `Monitor`, `Workflow`, `AskUserQuestion`, `ExitPlanMode`, `ScheduleWakeup`, `SendMessage`, `Skill`) | the first call of a parallel batch (results back within 10 s form one stall) | Codex records no approval events; a machine asleep mid-call also counts |
| `edit_without_read` | Claude: the harness rejected an `Edit`/`Write` with "has not been read yet" or "modified since read". Codex: `apply_patch` updates a path that no earlier read, patch, or shell command in the session named | the edit | Claude edits through Bash (`sed -i`) are not seen |
| `unverified_claim` | the last assistant reply before the next human turn (the handback) contains an ATTEST reserved word and no verifier pointer | the reply | a pointer is any of: exit code, `N/M` or `N of M`, `N passed`, `N tests`/`suites`/`checks`, `path:line`, `evidence:`, a backticked command followed by its result, `by \`cmd\``, a backticked commit hash or one after `@`/`commit`, a URL, a file path, a link to a local file. Sessions opened by a `claude -p` permission probe are skipped. A reply that cites a pointer for a different claim passes |
| `user_correction` | a human turn after the opening prompt that starts with no / nope / wrong (not "no need", "no luck", "no, that's fine", "X not needed"), is a bare "stop." / "stop it", or contains "I meant", "I said", "that's wrong", "not what I asked", "you're wrong" | the human turn | a declined proposal ("No. Park it.") still counts; a polite correction without these words does not. Telling the two apart needs the parked model signals |
| `recurring_failure` | a failure whose shape (tool + error text with paths, hex runs and numbers masked) an earlier session already hit. User rejections, exit 130 and a bare "Exit code N" do not count | the shape's first line in each later session | a reworded message for the same cause is a new shape; the first session to hit a shape is never cited |
| `recurring_action` | the same command shape (masked as above, 60+ characters) in 3 or more sessions of one project: a step worth writing once as a script, skill or instruction line | the third session's first use | shorter everyday commands are skipped on purpose; a command that is already a skill still fires |
| `no_progress_streak` | 4 or more runs in a row of one check (same command, paths kept) with the same exit code and error shape, while the session edited 1 to 3 files: the edits changed nothing the check sees | the first run of the streak | output that changes while the exit code stays the same still counts as the same result; a streak with no edit is polling and is skipped |
| `repeated_args` | the same tool with a byte-identical input of 200+ characters succeeds 5 or more times in one session (long-running tools skipped): an argument loop | the first call | a deliberate poll with a long script also fires |
| `loop_cost_outlier` | a session with 3 or more loop rows (`repeated_failure`, `no_progress_streak`) whose turns exceed 3x the median of its project's main sessions of 50+ turns (projects with 3+ such sessions). The floor keeps scheduled runs and probes out of the median | the session's first loop row | cost is shown when the transcript records it (Claude only); a long session that loops for a good reason still fires |

Reserved words (ATTEST-100 §3): done, complete(d), fixed, resolved, passing, passes, green, works, working, correct, safe, secure, verified, confirmed, proven, no regressions, production-ready. Phrases like "working tree", "safe to", "not yet done", "tell me when it's done", "how it works", "the green … button" are removed before matching.
